# 진열명 색상 편집 — 칩 + 팔레트 UX 설계

- 작성일: 2026-05-27
- 상태: 설계 확정 (구현 전)
- 관련 파일: [`TitleEditor.tsx`](../../entrypoints/sidepanel/ui/TitleEditor.tsx), [`lib/display-id/color.ts`](../../lib/display-id/color.ts)

## 1. 배경과 문제

현재 진열명 편집은 색상을 `단어#HEX, 단어#HEX` 형식의 **텍스트 한 칸**에 직접
타이핑한다 (예: `군인#008000, 꿀템#FFFF00`). HEX를 외워서 단어 뒤에 손으로 짝짓는
방식이라 번거롭다.

문구(강조 단어)와 색을 **분리**하고, 단어를 추가하면 색이 **자동 배정**되며,
단어별로 색을 쉽게 고를 수 있게 한다.

## 2. 핵심 원칙

**출력 형식은 바꾸지 않는다.** 저장값은 지금처럼 `단어#HEX, …` 문자열 그대로
`sectionExplain`에 들어간다. 바꾸는 것은 **입력 UX뿐**이다.

`lib/display-id/color.ts`의 파서/타입은 거의 그대로 두고, `TitleEditor`의 색상
입력 UI만 텍스트 칸 → 칩 + 팔레트로 교체한다.

## 3. 데이터 모델

```ts
// 색칠 규칙 한 줄 = 단어 + 색. 색은 팔레트에서 왔지만 "리터럴 hex"로 저장한다.
type ColorChip = { word: string; hex: string };

// 팔레트는 "색을 고르는 출처"일 뿐. 칩은 팔레트 인덱스가 아니라 hex 값을 들고 있다.
type Palette = string[]; // 예: ['#008000', '#FFD400', '#FF3B30']
```

- **칩은 `{word, hex}`** — 기존 `ColorRule`과 동일 구조라 `parseColorSpec`/직렬화를 재사용.
- **팔레트는 hex의 단순 출처**. 칩이 팔레트 인덱스를 참조하지 않으므로, 팔레트 색을
  바꿔도 이미 만든 칩 색은 안 흔들리고 `단어#HEX` 왕복이 깨지지 않는다.

## 4. UI 레이아웃

```
┌─ 진열명 편집 ──────────────────────────────┐
│ 진열명   [ {이름}님을 위한 군인 꿀템 ]      │
│                                            │
│ 강조 단어                                  │
│  [● 군인 ×] [● 꿀템 ×]  [+ 단어 입력…]      │  ← 칩 입력
│                                            │
│ 팔레트                          [＋ 색 추가]│
│  ● #008000  ● #FFD400  ● #FF3B30  ✎        │  ← 프리셋(세션 내 수정 가능)
│                                            │
│ 프리뷰: {이름}님을 위한 [군인] [꿀템]       │  ← 색 입혀서 렌더
└────────────────────────────────────────────┘
```

### 컴포넌트 분리 (작은 파일 우선)

- **`WordChips.tsx`** — 칩 목록 + 새 단어 입력. 각 칩은 좌측 색 스와치 + 단어 + × 삭제.
  스와치 클릭 → 팔레트 팝오버로 단어별 색 변경.
- **`ColorPalette.tsx`** — 프리셋 스와치 행 + 색 추가/수정/삭제 (세션 내).
- **`TitleEditor.tsx`** — 위를 조립하고 칩 → `단어#HEX` 직렬화로 기존 `onChange`
  계약 유지. 프리뷰 렌더(`renderColoredPreview`)는 그대로 재사용.

### 상태 소유

- 칩 목록 = `TitleEditor` 로컬 state (진열별, 저장 안 함)
- 팔레트 = `TitleEditor` 로컬 state, `DEFAULT_PALETTE`로 초기화 (세션 내 수정 가능,
  **저장 안 함** — 새로고침 시 프리셋으로 리셋)

## 5. 색 배정 + 단어별 선택

각 칩은 색을 팔레트에서 고른다. 단어를 추가하면 자동으로 한 색이 들어가 있고,
칩 스와치를 누르면 팔레트가 펼쳐져 다른 색으로 바꾼다.

```
[● 군인 ×]   ← 스와치 클릭
   │
   ▼ 팔레트 팝오버
 ┌────────────────────────┐
 │ ● 초록  ● 노랑  ● 빨강  │  ← 클릭하면 이 칩 색 = 그 색
 │ 색 직접 지정 [#______]  │  ← 즉석 커스텀 hex 허용
 │ (색 없음)               │  ← 색 해제(저장값에서 제외)
 └────────────────────────┘
```

동작 규칙:
- **추가 시 자동 배정**: 새 칩 기본색 = `palette[기존칩수 % 팔레트길이]` (라운드로빈).
- **단어별 변경**: 칩 스와치 클릭 → 팝오버 → 색 선택 = 그 칩만 변경. 다른 칩 영향 없음.
- **커스텀 hex**: 팝오버에서 직접 hex 지정 가능. 커스텀 색도 칩엔 hex로 저장돼 왕복 동일.
- **색 안정성**: 칩이 hex를 자기가 들고 있어 다른 칩 추가/삭제 시 색이 안 흔들림.
  자동 배정은 "추가하는 순간"에만 작동.
- **색 해제**: "색 없음" 선택 시 그 단어는 직렬화에서 빠짐(=색 안 칠함).
- **팔레트 비면**: 자동 배정은 `DEFAULT_PALETTE`로 폴백.

## 6. 기존 진열 불러오기(왕복)

- 진열 편집 진입 시 기존 `색상 규칙` 원문(`군인#008000, 꿀템#FFFF00`)을
  `parseColorSpec`으로 **1회** 파싱 → `ColorChip[]`로 칩 복원.
- 파싱 에러(잘못된 hex 등)는 기존 검증 로직대로 오류/경고 표시. 정상 칩만 복원하고,
  못 살린 원문은 경고로 노출(데이터 유실 방지).
- 칩 hex가 현재 팔레트에 없어도 그대로 표시(커스텀 색 취급).

## 7. 직렬화 (변화 없음)

`chips.map(c => \`${c.word}#${c.hex}\`).join(', ')` → 기존
`onChange({ title, color, hasError })`. `TitleResult` 계약·`sectionExplain` 채우기
로직은 손대지 않는다. "색 없음" 칩은 제외.

## 8. 테스트

기존 `TitleEditor.test.tsx` / `color.test.ts` 골격을 따른다.

**유닛 (`color.ts`)** — 파서는 그대로 유지. 직렬화 헬퍼 추가 시:
- 칩 배열 → `단어#HEX, …` 문자열 정확히 생성
- "색 없음" 칩은 직렬화에서 제외

**컴포넌트 (`WordChips`, `ColorPalette`, `TitleEditor`)**
- 단어 입력 후 Enter → 칩 추가 + 자동색 = `palette[0]`
- 두 번째 칩 → `palette[1]` (라운드로빈)
- 칩 스와치 클릭 → 팔레트 색 선택 → 그 칩만 변경, 직렬화 반영
- 커스텀 hex 입력 → 칩 색 반영
- "색 없음" → 직렬화에서 제외
- 진열명에 없는 단어 → 경고 배지 (기존 로직)
- 기존 원문 `군인#008000, 꿀템#FFFF00` 주입 → 칩 2개로 복원
- 팔레트 색 추가/삭제 → 자동배정 후보 변화

시각 회귀(스와치/팝오버)는 필요 시 Playwright 스크린샷으로 보조.

## 9. 범위에서 제외 (YAGNI)

- 팔레트 영속 저장 / 진열 간 공유 (세션 리셋으로 충분)
- 칩 드래그 재정렬, 진열명에서 클릭 선택
- "팔레트에 추가" 같은 커스텀 색 승격 버튼 (추후)
