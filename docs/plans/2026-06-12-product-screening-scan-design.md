# 상품심사 일괄 스캔 (Product Screening Scan)

날짜: 2026-06-12
상태: 설계 확정 (구현 대기)

## 배경 / 문제

샵바이 어드민 상품심사 화면에는 승인대기 상품이 수십~수백 건 쌓인다. MD는 상품마다
승인상태를 클릭해 심사 팝업(`/popup/product-screening?globalProductNo=0&mallProductNo={상품번호}`)을
열고, 기본정보·판매정보·이미지·배송정보를 눈으로 훑어 잘못된 값을 찾아야 한다.
상품당 수십 개 항목을 사람이 전수 검사하는 구조라 누락이 잦고 느리다.

익스텐션이 목록의 상품번호를 전부 추출해 심사 팝업 정보를 자동 수집하고,
MD가 미리 정한 규칙(필수값·기대값·이미지)에 비춰 위반 상품만 골라 보여주면
"어떤 상품부터, 무엇을 봐야 하는지"가 즉시 드러난다.

## 확정된 결정 사항

| 결정 | 선택 |
|---|---|
| 데이터 수집 | 숨김 탭 순회 스크래핑 — 심사 팝업을 비활성 탭으로 열고 content script가 렌더된 DOM을 파싱 |
| 규칙 정의 | 사이드패널에서 MD가 설정 (`chrome.storage.local` 저장) |
| v1 검사 유형 | 공란/필수값 · 기대값/범위 · 이미지 체크 (일관성 체크는 v2) |
| 결과 UX | 사이드패널 「심사」 탭 — 위반 배지 리스트, 카드 클릭 시 해당 심사 팝업 열기 |
| 액션 범위 | 읽기 전용. 플래그 + 팝업 열기까지만. 승인/거부/체크는 사람이 직접 |
| 스캔 범위 | "200개 보기" 전환 후 페이지네이션 끝까지 순회 |
| 시드 규칙 | 기본 규칙 세트를 제공하되 전부 OFF(선택 안함) 상태로 시드. MD가 켜서 사용 |
| 결과 보존 | 세션 메모리만. storage 저장 안 함 (심사 대기열은 휘발성 데이터) |

## 아키텍처

기존 구조(사이드패널 탭 + `*.shopby.co.kr` allFrames content script + background 중계)를 따른다.

```
사이드패널 「심사」 탭 (신규)
  ├─ 규칙 설정 UI  ←→ chrome.storage.local
  ├─ [스캔 시작] ─▶ background ─▶ 목록 페이지 content script
  └─ 결과 리스트 (위반 상품 + 배지, 스트리밍 갱신)

목록 페이지 수집기 (content script, 신규)
  1. "200개 보기"로 전환 → 그리드 리로드 대기
  2. TUI 그리드는 가상 스크롤 → 바디를 프로그램으로 스크롤하며
     상품번호(`[data-column-name="productNo"]`)·상품명 수집
  3. "검색결과 총 N건"과 대조해 완수 확인
  4. 다음 페이지 버튼 클릭 → 반복 (끝까지)

상세 수집 오케스트레이터 (background, 신규)
  상품번호마다 순차로:
  chrome.tabs.create({ active: false, url: 심사 팝업 URL })
  → 팝업 파서가 결과 반환 → 탭 닫기 → 진행률 중계 (n/total)
  실패 시 1회 재시도, 큐·재시도 로직은 순수 함수로 분리

심사 팝업 파서 (content script, 신규)
  기본정보/판매정보/이미지정보/배송정보/상품항목추가정보 테이블을
  { 섹션: { 항목명: 값 } } 레코드로 파싱 + 이미지 src 목록 수집
```

수집 완료된 레코드는 순수 함수 규칙 엔진을 거쳐 위반 목록이 되고,
상품 하나가 끝날 때마다 사이드패널 결과에 즉시 추가된다(스트리밍).
78건 기준 예상 소요 약 2분. 진행률과 중단 버튼 제공.

## 규칙 모델

```ts
type Rule =
  | { id: string; type: 'required';            // 공란/필수값
      section: SectionName; field: string;      // 예: '기본정보' / '제조사명'
      enabled: boolean }
  | { id: string; type: 'expected';            // 기대값/범위
      section: SectionName; field: string;
      op: 'equals' | 'notEquals' | 'includes' | 'gt' | 'gte' | 'lt' | 'lte';
      value: string;                            // "15%" → 15, "4,500 원" → 4500
      enabled: boolean }
  | { id: string; type: 'image';               // 이미지 체크
      kind: 'mainRequired' | 'listRequired' | 'detailMin' | 'externalHost';
      threshold?: number;                       // detailMin: 최소 장수
      allowHosts?: string[];                    // externalHost: 허용 호스트(shopby CDN 기본)
      enabled: boolean }
```

- **필드는 자유 입력이 아닌 드롭다운**: 팝업 항목명 카탈로그를 섹션별로 내장,
  오타로 규칙이 영원히 안 걸리는 사고를 차단.
- 숫자 비교는 표기("140,000원", "15%", "0kg")에서 숫자만 추출해 비교.
  추출 실패 시 조용히 통과시키지 않고 "비교 불가" 위반으로 표면화.
- 시드 규칙(전부 OFF): 제조사명 필수, 제품모델명 필수, 상품 중량 > 0,
  대표이미지 필수, 상세이미지 ≥ 1장.

### 규칙 엔진

```ts
evaluate(product: ParsedProduct, rules: Rule[]): Violation[]
// Violation = { ruleId, section, field, message, actual }
```

## 심사 탭 UI

```
┌─ 심사 탭 ──────────────────────────────┐
│ ▸ 규칙 설정 (접이식, 기본 접힘)            │
│   [+ 규칙 추가] / 규칙별 enabled 토글     │
├────────────────────────────────────────┤
│ [▶ 스캔 시작]  ⏸ 중단                    │
│ ████████░░░░  34 / 78  (실패 1 · 재시도) │
├────────────────────────────────────────┤
│ 결과: 위반 12건 / 정상 21건  [위반만 보기] │
│ ⚠ 133770595 [디라이프] 쿡 웨어 IH …      │
│    · 제조사명 공란 · 중량 0kg             │
│ ✅ 133681147 OIC 304 … (0건)            │
└────────────────────────────────────────┘
```

- 정렬: 위반 개수 내림차순 기본. "위반만 보기" 토글.
- 카드 클릭 → 해당 상품 심사 팝업을 활성 탭으로 열기.
- 수집 실패 상품은 "수집 실패" 카드로 표시 (침묵 누락 금지).

## 에러 처리 / 엣지 케이스

- **렌더 완료 감지**: 고정 지연 대신 MutationObserver —
  주요 섹션이 모두 존재하고 행 수가 안정화될 때까지 대기. 타임아웃 15초 → 재시도 1회.
- **목록 수집 검증**: 수집 건수 ≠ "총 N건"이면 결과 상단에 경고 배너.
- **세션 만료**: 팝업이 로그인 화면으로 리다이렉트되면 감지 → 스캔 전체를
  "세션 만료"로 즉시 중단 (연속 실패 방지).
- **중단**: 진행 중 탭 닫고 대기열 폐기, 수집된 결과는 유지.
- **항목명 충돌**: 섹션 키로 네임스페이스 분리.

## 테스트 전략

| 대상 | 방식 |
|---|---|
| 팝업 파서 | 심사 팝업 HTML 픽스처(`tests/fixtures/`) + jsdom → 섹션·항목·이미지 src 단언 |
| 규칙 엔진 | 순수 함수 단위 테스트 — 공란/기대값/숫자 파싱/비교불가 케이스 |
| 목록 수집기 | 그리드 HTML 픽스처로 상품번호 추출·총건수 대조 로직 |
| 심사 탭 UI | Testing Library — 규칙 토글·정렬·위반만 보기·진행률 |
| background | chrome API 의존 최소화 — 큐·재시도 카운트를 순수 함수로 분리해 테스트 |
